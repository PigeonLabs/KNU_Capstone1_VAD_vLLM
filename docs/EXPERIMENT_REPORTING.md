# 실험 종료 보고 규칙

각 실험 종료 시 아래 네 항목을 상세 보고서와 README 요약에 남긴다. 기존 실험 01·02에도 같은 형식을 적용한다. 사용자에게 전달하는 완료 보고에도 이 네 항목의 핵심을 포함한다.

## 1. 이번 실험 결과

- 질문, 직전 실험에서 선택한 변경과 이유, 고정한 조건을 명시한다.
- 데이터 범위, fit/calibration/test 분할, seed, 평가 프레임 수, 실행 완료 여부를 기록한다.
- AUROC/AP와 정상 calibration에서 정한 임계값의 오탐률·recall을 함께 표로 비교한다. 서로 다른 임계값의 비교인지 명시한다.
- phase 관측률, 검출 품질, 누락 길이 등 해당 변경을 설명하는 진단치를 보고한다. 측정하지 않은 항목은 미측정으로 남긴다.
- 비용·지연은 측정한 경우에만 측정 범위와 함께 기록한다. 설정, 기계 판독 결과, 영상별 결과, 그래프, 재현 명령을 연결한다.

## 2. 실험 결과의 의의

관측이 뒷받침하는 결론과 아직 검증하지 않은 가설을 구분한다. 파이프라인 구현 및 구성 요소의 역할을 확인한 가치를 설명하되, 성능 상승 자체를 novelty로 간주하지 않는다. 단일 장면·seed의 기술 통계로 통계적 유의성이나 일반화를 주장하지 않는다. 논문 주제는 결과가 쌓이기 전에 고정하지 않는다.

## 3. 보완할 점

결과에서 확인한 실패, 오탐/recall의 상충, 관측 및 정답의 부족, 비교의 혼입 요인, 다른 장면으로의 적용 한계를 근거와 함께 기록한다. 원본 라벨 정렬의 미해결 문제를 임의 보정으로 숨기지 않는다. 관측률을 검출 recall 또는 phase 정확도로 대체하지 않는다.

## 4. 다음 Recommended improvements — 추천순 3개

정확히 세 후보를 다음 표로 정리한다. 예상 효과는 검증할 가설이며 성능 향상 약속이 아니다.

| 추천순 | 개선 후보와 변경 내용 | 이번 결과의 근거 | 검증 기준 및 주의점 |
|---|---|---|---|
| 1 | 가장 먼저 검증할 후보 | 측정치 또는 관찰 | 효과와 부작용을 함께 판정할 기준 |
| 2 | 두 번째 후보 | 측정치 또는 관찰 | 효과와 부작용을 함께 판정할 기준 |
| 3 | 세 번째 후보 | 측정치 또는 관찰 | 효과와 부작용을 함께 판정할 기준 |

다음 실험을 진행할 때 이 중 우선 후보의 구체적인 변경을 선택한다. 세 후보를 세 개의 확정 실험으로 취급하거나 모두 동시에 도입하지 않는다. 새 결과가 나오면 우선순위를 다시 정한다. 테스트 라벨로 임계값·모델을 선택하지 않으며, 반복 관찰한 장면은 개발용으로 취급한다. 별도 bbox 주석을 평가에 사용하면 normal-only 학습과 보조 진단용 주석의 범위를 구분한다.

## 저장 및 업로드

상세 보고서는 `docs/EXPERIMENTXX.md`, 재현 가능한 설정과 결과는 기존 `configs/`·`results/` 구조를 따른다. README에는 결과 표/필요한 그래프, 의의, 보완할 점, 추천순 3개와 상세 링크를 유지한다. 수치·링크·변경 내용을 검사한 뒤 실험 단계별로 GitHub에 업로드한다. 원본 데이터·가중치·특징 캐시·서버 로그는 제외한다.
